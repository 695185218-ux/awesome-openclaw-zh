## 403 Forbidden（最常见）

403 表示"没有权限"。以下是最常见的 5 种原因和解法：

### 1) API Key 权限不足

**现象**：调用 Skill 或渠道时返回 403。

**解法**：
- 进入你使用的 AI 模型供应商后台（如 OpenAI、Anthropic 等），确认 API Key 有对应的调用权限。
- 如果是免费额度用完，充值或换 Key。
- 确认 Key 没有被撤销或过期。

### 2) Skill 未授权

**现象**：安装了某个 Skill，但调用时返回 403。

**解法**：
- 在 OpenClaw 后台检查该 Skill 是否已正确授权。
- 有些 Skill 需要单独的 OAuth 授权（如 Google、Notion），点进 Skill 设置页重新授权。
- 外部 Skill 可能需要在对应平台（如 GitHub、Slack）开启 API 访问权限。

### 3) 协作/Cowork 模式权限不对

**现象**：多人协作（cowork）或跨 Bot 协作时，其中一方显示 403。

**解法**：
- 确认所有参与协作的 Bot 都绑定了有效的 API Key。
- 确认每个 Bot 对共享资源（如 Google Drive、Notion 页面）都有访问权限。
- 如果使用共享 Workspace，确认你的账号已被邀请并接受。
- 多实例协作时，每个实例需要独立授权，不能共用同一个会话 Token。

### 4) 渠道 Token 过期

**现象**：之前能用，突然 403。

**解法**：
- Telegram Bot Token 一般不会过期，但如果你重新生成过就会失效——用新 Token 替换。
- 飞书/企业微信的 Token 有有效期，需要刷新或重新获取。
- Slack Bot Token 如果 workspace 权限变更也会失效，重新安装 App 即可。

### 5) 访问频率限制（Rate Limit）

**现象**：短时间大量请求后出现 403 或 429。

**解法**：
- 降低自动化任务的执行频率。
- 参考 [低成本稳定运行](./01-low-cost-stable-run.md) 中的频率控制建议。
- 如果是 API 供应商限制，等几分钟后重试。

## 快速自查清单

遇到 403 时，按顺序检查：

1. **API Key 有效吗？** → 后台确认未过期、未撤销、有余额
2. **Skill 授权了吗？** → Skill 设置页确认 OAuth 状态为"已连接"
3. **协作方都有权限吗？** → 每个 Bot/用户都需要独立授权
4. **Token 还有效吗？** → 渠道设置页确认连接状态
5. **是不是请求太频繁？** → 降低频率，等几分钟重试

## 其他常见错误

| 错误码 | 含义 | 最常见原因 |
|---|---|---|
| 401 | 未认证 | API Key 格式错误或未填写 |
| 403 | 无权限 | 见上方详细排查 |
| 429 | 请求过多 | 降低频率或升级配额 |
| 500 | 服务端错误 | 等几分钟重试，不是你的问题 |
| 502/503 | 服务不可用 | 上游服务临时故障，稍后重试 |
